# M10：主题

2026-11-24 设计。**只有设计，没有代码**：用户说先设计好，决定做了再开始写。

## 目标（用户 2026-11-24 的原话归纳）

1. 自带几套默认主题。
2. 允许自己写主题配置文件。
3. 执行一条主题切换命令就能换。
4. 每次打开后用上次设置的主题。

验收标准：

- `ut theme` 列出主题，当前的一个有标记。
- `ut theme NAME` 之后 1 秒内，所有开着的窗口换成那套颜色；不用重开。
- 关掉再打开，颜色还是那一套。
- 把一个文件放进主题目录，`ut theme` 里就有它，`ut theme 它的名字` 能切过去。
- 名字不存在或文件写错：命令拒绝并说明原因；窗口保持现在的颜色。
- 不设置主题的用户，颜色和 0.3.0 逐像素相同。

## 现状（读代码得到的事实）

- 一套主题是 20 个颜色：前景、背景、光标、选区、16 个 ANSI 色（`crates/unifyterm/src/theme.rs`）。256 色里其余 240 个由它们算出。
- 内置只有一套（Tokyo Night）。设置文件的 `[theme]` 有 5 个键，可以逐个覆盖颜色。
- 标签栏、弹窗、列表、侧栏的颜色都从这 20 个颜色算出来（`toward`），`theme.rs` 之外没有写死的颜色。
- 窗口每 0.5 秒看一次设置文件，颜色在下一帧生效。
- 程序问终端"背景是什么颜色"（OSC 10/11）时，已经按主题回答。
- 窗口不知道系统是浅色还是深色，也不告诉系统自己是哪一种。

结论：换主题需要的机制（热更新、保存、派生颜色）已经都有。缺的只是"给一套颜色起名字"和"按名字选"。

## 用香农六法得出的决定

| 方法 | 结论 |
|---|---|
| 简化 | 主题 = 起了名字的 20 个颜色。切换 = 改一个设置项 `theme.name`。保存和热更新用现成的设置文件机制，不另造 |
| 相似问题 | Ghostty（`theme = 名字`，一个主题目录，`+list-themes`）、WezTerm（`color_scheme = "名字"`）、kitty（`kitten themes`）都是"一个名字 + 一个目录"。照这个做法 |
| 换说法 | "主题切换命令"不是给窗口发消息，是"改设置文件的一个值"。所以命令在窗口没开时也能用，对所有窗口同时生效 |
| 推广 | 内置主题和用户的主题用同一种文件、同一段读取代码：内置的只是编译进程序的文件。`ut theme show` 打印内置主题，就是用户写自己主题的起点 |
| 结构分析 | 三件事分开：一套颜色从哪来（名字 → 文件）；名字存在哪（设置文件）；谁来改名字（`ut theme`、`ut setting`、手改文件，三者等价） |
| 逆向 | 最坏的结果是换完主题看不清字、又换不回来。所以：切换前先检查文件；检查不过不写设置；`ut theme` 的输出不依赖主题也能读（用终端默认色）；再加一条"前景和背景对比度太低时提醒" |

## 设计

### 设置项

新增 1 个：`theme.name`，默认 `"tokyo-night"`。设置项 35 → 36。

颜色的来源，后面的盖住前面的：

1. `theme.name` 指的主题（找不到时用内置的 Tokyo Night）。
2. 设置文件 `[theme]` 里单独写的颜色（`theme.background` 等 5 个键，现有行为不变）。

这样现在已经在 `[theme]` 里改过颜色的用户，升级后看到的一样。

### 主题文件

一个主题一个 TOML 文件，键与 `[theme]` 相同：

```toml
# 文件名就是主题名：my-night.toml → my-night
foreground = "#c0caf5"
background = "#16161e"
cursor = "#c0caf5"        # 可省：用 foreground
selection = "#33467c"     # 可省：前景往背景靠 70% 的颜色
ansi = [                  # 16 个：黑红绿黄蓝紫青白，再是亮的 8 个
  "#15161e", "#f7768e", "#9ece6a", "#e0af68", "#7aa2f7", "#bb9af7", "#7dcfff", "#a9b1d6",
  "#414868", "#f7768e", "#9ece6a", "#e0af68", "#7aa2f7", "#bb9af7", "#7dcfff", "#c0caf5",
]
```

- `foreground`、`background`、`ansi` 必须有。原因：缺了就得从别的主题借，深色和浅色会混在一起。
- 不认识的键报错（防止拼错键名而不自知）。
- 名字只能是小写字母、数字和 `-`。

### 放在哪里

| 什么 | 位置 |
|---|---|
| 内置主题 | 仓库的 `themes/*.toml`，编译进程序 |
| 用户的主题 | 设置文件旁边的 `themes/` 目录（Windows：`%APPDATA%\unifyterm\themes\`） |

用户目录里与内置同名的文件优先：想微调内置主题，复制出来改即可。

### 命令：`ut theme`

```
ut theme                  列出主题：名字、内置还是自己的、一行色块；当前的有标记
ut theme NAME             切到 NAME：检查后把 theme.name 写进设置文件
ut theme show NAME        打印这个主题的文件内容（内置的也行）
ut theme new NAME [--from NAME]   在主题目录里建一个文件，内容抄自当前主题或 --from 的主题
ut theme check FILE       只检查一个文件
ut theme directory        打印主题目录
```

- 色块用真彩色转义序列打印，在任何支持真彩色的终端里都看得到主题的颜色，不用先切过去。
- `ut theme NAME` 写设置文件用 `ut setting` 现有的那段代码（保留文件里的注释和顺序）。
- `ut setting` 的界面里 `theme.name` 是一个可选列表（内置的加目录里的），不用打字。

### 窗口一侧

- 读设置时按 `theme.name` 取颜色。名字找不到或文件有错：保持现在的颜色，在标签页里说一行原因（与设置文件写错时相同），日志里记下。
- 正在用的主题文件也纳入每 0.5 秒的查看：改主题文件，窗口立即跟着变。写主题的人可以边改边看。用 M9 里加的"时间戳太新就过后再读一次"的规则。
- 把"现在是浅色还是深色"告诉系统（按背景色的亮度算）。原因：Windows 标题栏上的三个按钮、macOS 的红绿灯和系统画的边框要跟着变。这一项要先查 GPUI 0.2.2 能不能做到，做不到就写进已知限制。

## 浅色主题要查的地方

现在只有一套深色主题在用，下面这些在浅色下没人看过。实现时每一处截图看：

1. 标签栏、当前标签、关闭按钮。
2. 输入行下面的列表、弹窗（纠正、解释、同意）。
3. 灰色建议（前景往背景靠出来的颜色，浅色下够不够淡又看得清）。
4. agent 侧栏。
5. `ut setting` 自己的界面（它在终端里画，用 ANSI 色）。
6. `ut md`、`ut view` 的回退字符画。
7. 选区的文字是否还看得清。

## 不做的

| 项目 | 原因 |
|---|---|
| 跟随系统的浅色和深色自动切换 | 用户没有要。做的话是两个设置项（浅色时用哪套、深色时用哪套），可以以后加，不影响这次的文件格式 |
| 读别的终端的主题文件（kitty、Alacritty、Windows Terminal） | 先一种格式。以后加 `ut theme import FILE` 即可，不改现有的东西。iTerm2-Color-Schemes 有几百套现成的 |
| 在列表里上下移动时实时预览 | 色块已经能看出大概；切换本身只要一条命令、1 秒内生效，试一套的成本很低 |
| 主题里带字体、透明度、标签栏样式 | 主题只管颜色。其他的是设置项 |
| 窗口里的快捷键轮换主题 | 没有要 |
| 标签栏、弹窗的颜色单独指定 | 现在都从 20 个颜色算出来，一套主题不用多写。等有人觉得算出来的不好看再加 |

## 步骤（决定做之后）

1. `crates/config` 加 `themes`：读主题文件、内置表、按名字找、`theme.name` 这个设置项。单元测试：每套内置主题都能读；前景对背景的对比度不低于 7:1；先后顺序（主题 → `[theme]` 的键）。
2. 窗口：按名字取颜色；主题文件纳入查看；出错时的提示。
3. `ut theme`；`ut setting` 里的可选列表。
4. 10 套主题的文件，逐套核对许可和颜色值。
5. 浅色下的 7 处逐个截图，改掉看不清的。
6. 告诉系统深浅（先查 GPUI 能不能做）。
7. README、网页的数字（36 个设置）、`ut --help`。
8. 实机检查加一节：切换后背景像素变了；重开后保持；名字写错时不变。三轮验收。

估计改动量：新代码 600 到 900 行（不含主题文件），其中一半是测试。
