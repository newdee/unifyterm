# M10：主题

2026-11-24 设计。当天晚些时候用户加了六套主题文件（`demo/themes/`）和预览页（`demo/appearance.html`），要求窗口和预览页一致、标签栏能自动收起、透明度能配置：开始实现。下面"实现时改动的决定"一节记录与原设计不同的地方；其余各节是原设计，没有改写。

## 实现时改动的决定

| 原设计 | 实现 | 原因 |
|---|---|---|
| 自带 10 套公开配色 | 自带 7 套：`tokyo-night` 和用户的六套（`aurora`、`eclipse`、`phosphor`、`riso`、`night`、`day`） | 用户给了自己的六套。不引入别人的配色，也就没有许可要核对 |
| 内置主题放仓库的 `themes/` | 留在用户放的 `demo/themes/`，编译进程序 | 预览页的下载链接指向那里；一份文件，不复制 |
| 主题文件的键在文件顶层 | 文件里一个表 `[theme]`，键与设置文件的 `[theme]` 相同 | 用户的六个文件就是这样写的；`unifyterm --config 主题文件` 因此也能用 |
| 标签栏、弹框的颜色都从 20 个颜色算，不单独指定 | 加 7 个可省的键：`bar`、`panel`、`well`、`rule`、`edge`、`muted`、`symbol` | 量过：按"背景往前景靠"算出来的颜色，和预览页的值最多差 29（满值 255，`riso` 的 `edge`）。要和预览页一致，只能把值写进主题文件。省掉的键仍然算出来，比例取六套主题的中位数（3.5%、6.5%、11%、19%、33%、77%） |
| 不设主题的用户，颜色和 0.3.0 逐像素相同 | 终端里的文字和背景相同；标签栏、列表、弹框、侧栏按预览页重画，不相同 | 用户要窗口和预览页一致，这些东西的形状变了 |
| 设置项 35 → 36 | 35 → 49：`theme.name`、7 个界面色、`theme.opacity`、`theme.blur`、`theme.picture`、`theme.rounding`、`theme.corners`、`window.tab_bar` | 多了：界面色、自动收起、透明度、毛玻璃、图、圆角 |
| 名字找不到时在标签页里说一行 | 开窗口时在标签页里说；窗口开着时只写日志，颜色不变 | 与设置文件写错时的现有做法相同 |
| 告诉系统窗口是深色还是浅色 | 没做 | 标题栏是自己画的，三个按钮跟着主题走；系统画的边框没有处理 |
| `ut theme` 的命令 | 与设计相同，另加 `ut theme use NAME`（与 `ut theme NAME` 相同） | 名字与子命令相同时还能选 |

设计里没有、实现时加的：

| 加了什么 | 原因 |
|---|---|
| 浅色主题下，白色字在主题自己的背景上改用主题的文字色 | PowerShell 把输入的词写成白色。浅色主题的白色和背景几乎一样（`day`：对比度 1.2），不能把白色改深（蓝底白字要保持浅色）。只在"白或亮白 + 主题背景 + 对比度低于 2"时改，深色主题不受影响（有测试） |
| 标签栏高 46 像素，预览页是 54 | 标签栏同时是标题栏，54 会从文字区再拿走半行。标签本身的尺寸（高 36、最小宽 112、圆角 7、短线 30×2）照预览页 |
| 列表多一行标题（"Command history"，右边是按键提示） | 预览页有 |
| Agents 侧栏宽 268（原 300），有标题行和关闭按钮，卡片有边线 | 预览页的样子 |

预览页里有、窗口没做的：

| 没做 | 原因 |
|---|---|
| 提示符上面的"路径 · 分支"、`❯`、输出左边的竖线 | 那是 shell 的提示符和输出，终端不画 |
| 右上角"历史 / 解释 / Agents"三个按钮、底部状态栏 | 新的界面元素，放下一步；这一步只重画已有的东西（侧栏下方的主题画后来做了，见下） |
| `phosphor` 的下划线光标、`riso` 的硬投影、`eclipse` 的渐变短线 | 名字已占好（见"以后可加的字段"），没实现。`phosphor` 的方角后来做了：`rounding = 2`、`corners = "small"` |
| Agents 卡片上的"运行中 / 等待输入" | keepane 给的数据里没有这一项 |
| 中文界面 | 程序界面是英文，没有多语言 |
| 文字区四周 24 像素的留白 | 是设置项 `terminal.padding`（默认 6），改默认会改掉所有人的行列数 |

标签栏自动收起（`window.tab_bar = "auto-hide"`）的做法：

- 收起时不占位置；出现时盖在文字上面，终端的行数不变（不触发程序重排）。
- 出现的条件：鼠标在窗口顶边 10 像素内停留 150 毫秒；或开、关、切换标签（显示 1.5 秒）。快速划过顶边不算。
- 收起的条件：鼠标离开到标签栏下方 12 像素以外。
- 10 像素的原因：Windows 把没有最大化的窗口顶部 4 像素留作调整大小，鼠标在那里窗口收不到消息。
- macOS 上标签栏是标题栏时，系统的红绿灯按钮画在里面，拿不掉：只在全屏时收起。

透明度（`theme.opacity`，0.1 到 1）：只有文字的背景、标签栏、侧栏透出后面；文字、列表、弹框不透。在真实屏幕上量过（Windows 11）：一个红色背景的窗口放在蓝色背景的窗口后面，蓝窗口不透明度 1 时读到 `#0000ff`，0.5 时 `#80007f`，0.25 时 `#bf0040`。

### 用户看过第一版窗口后加的（同日）

用户的话和对应的做法：

| 用户说的 | 做法 |
|---|---|
| 侧栏的插画不能显示吗 | 六张图用预览页自己的绘图代码画（2 倍尺寸，960×496），存成 PNG 编进程序，侧栏底部高 180 显示，上方按侧栏底色渐隐到 54%（与预览页相同） |
| 用代码画会不会更好，存成图片会失真吗 | 不会失真：PNG 无损；显示宽 268，屏幕缩放 276% 以下都是缩小。用 GPUI 重画反而做不到一致（预览页用了径向渐变、发光阴影、逐列渐变，GPUI 只有两个色标的线性渐变） |
| 图片能否在主题文件里指定；保持统一和可扩展 | 主题文件加 `picture` 键，路径相对写它的那个文件。内置主题的文件里也这样写（`picture = "aurora.png"`）。自带的六张图按文件名在任何文件夹里都找得到：`ut theme new` 抄出来的主题图还在 |
| 毛玻璃这类效果也要能配 | `blur`（布尔）。Windows 用亚克力，macOS 用系统的模糊，Wayland 用模糊协议，X11 没有 |
| 侧栏宽度和图片宽度不一致 / 渲染位置不对 | 第一版的图没按侧栏边界裁掉，画到了文字区上。定性：个性（只有这一处用"铺满并裁掉"）；边界遗漏（GPUI 的图片元素按比例铺满后不自己裁，要外层裁）。改：外层 `overflow_hidden`。实机检查里加了"侧栏旁边的文字区 24150 个像素全是文字背景色" |
| 透明度 | 从 `window.opacity` 挪成 `theme.opacity`：外观的东西都在 `[theme]`，主题能给，设置能盖 |
| 主题文件还有什么可以指定的字段，为以后兼容做好准备 | 见下面"以后可加的字段"。现在改的一条规则：主题文件里这个版本不认识的键和表跳过，不报错，`ut theme check` 点名 |
| 标签的圆角是否可以配置 | `rounding`（0 到 18 像素，默认 7）。标签和卡片用它；列表和弹框按预览页的比例是它的 8/7，小按钮是 5/7 |
| 开启隐藏标签栏的快捷键 | Ctrl-Shift-B（macOS：Cmd-Shift-B）：对当前窗口在"常显"和"自动收起"之间切换，不写设置文件；设置里的 `window.tab_bar` 一改，就以设置为准 |
| 终端的圆角也可以配置 | `corners`：`"round"`、`"small"`、`"square"`。系统画窗口外形，程序只能在系统给的形状里选，只有 Windows 11 能选 |
| 圆角足够大时终端能不能变成圆形 | 能，但要窗口整体透明、自己画外形。用户定：这一批验收、发版之后再做。届时 `corners` 多收一个数字（像素），现在的三个词仍然有效 |

`[theme]` 现在的键（18 个）：`name`（只在设置文件里）、12 个颜色键、`ansi`、`opacity`、`blur`、`picture`、`rounding`、`corners`。

### 以后可加的字段（现在不实现，名字先占好）

主题文件对不认识的键是"跳过并点名"，所以以后加字段不会让旧版本读不了新主题。下面的名字将来按这个意思用，不拿去作别的用途：

| 键 | 意思 | 为什么可能要 |
|---|---|---|
| `corners = 数字` | 窗口外形的圆角半径，像素；大到一半高度就是胶囊形 | 用户已提出，下一步做 |
| `kind = "dark" \| "light"` | 主题是深色还是浅色 | 做"跟随系统深浅"时要知道每个主题是哪一种；现在可以从背景亮度算，写明更可靠 |
| `title`、`author`、`license` | 给人看的名字（"极光"）、作者、许可 | 主题多了、互相分享时要有；放 `[theme]` 里，或单独一个 `[about]` 表（别的表现在也是跳过） |
| `cursor_text` | 块状光标下面那个字的颜色 | 现在用背景色；有的配色里光标色和背景色接近，字会看不清 |
| `selection_text` | 选中文字的颜色 | 现在不变色；浅色主题里选区深时要反色 |
| `bold` | 粗体字的颜色 | 一些配色给粗体单独的颜色 |
| `link` | 可点的网址的颜色 | 还没有可点的网址；有了以后要 |
| `palette = { 16 = "#…" }` | 256 色里第 16 到 255 号的单独指定 | 现在按 xterm 的公式算；少数配色想改其中几个 |
| `dim` | 暗字往背景靠多少（现在固定 0.4） | 浅色主题里 0.4 可能太淡 |
| `cursor_shape` | 光标的形状：块、竖线、下划线 | 预览页的 `phosphor` 是下划线光标。程序自己要的形状（DECSCUSR）仍然优先 |
| `shadow = "soft" \| "hard" \| "none"` | 列表和弹框的投影 | 预览页的 `riso` 是不模糊的硬投影 |
| `mark = "#…"` 或两个颜色 | 当前标签下短线的颜色，两个颜色时是渐变 | 预览页的 `eclipse` 是从琥珀到红的渐变。现在用光标色 |
| `wallpaper`、`wallpaper_opacity` | 文字区后面的图 | 常见的要求；与 `picture`（侧栏的图）是两样东西，所以不叫同一个名字 |
| `picture_height`、`picture_fade` | 侧栏那幅图的高度、渐隐到哪里 | 现在固定 180 像素、54% |
| `padding` | 文字离窗口边多远（现在是设置项 `terminal.padding`） | 预览页是 24。它会改行列数，是否算"外观"到时再定 |
| `font` | 字体 | **不打算做**：字体是每台机器装了什么的问题，放主题里换机器就坏。占着名字只为不被拿去作别的用途 |

不占名字、也不打算进主题文件的：按键、shell、历史、模型这些与外观无关的设置。

发版时顺带修的：`ut setting set` 对"数字"类设置的范围检查按 f64 比较，而设置按 f32 保存；下限 0.1 的 f32 值比 0.1 大一点，输入 `0.1` 会被拒绝。个性（只有这一处）；边界遗漏（以前的上下限 6、72、1、2、0、64 都能精确表示）。改成按 f32 比较。

以下是原设计。

## 目标（用户 2026-11-24 的原话归纳）

1. 自带几套默认主题。
2. 允许自己写主题配置文件。
3. 执行一条主题切换命令就能换。
4. 每次打开后用上次设置的主题。

验收标准：

- `ut theme` 列出主题，当前的一个有标记。
- `ut theme NAME` 之后 1 秒内，所有开着的窗口换成那套颜色；不用重开。
- 关掉再打开，颜色还是那一套。
- 把一个文件放进主题目录，`ut theme` 里就有它，`ut theme 它的名字` 能切过去。
- 名字不存在或文件写错：命令拒绝并说明原因；窗口保持现在的颜色。
- 不设置主题的用户，颜色和 0.3.0 逐像素相同。

## 现状（读代码得到的事实）

- 一套主题是 20 个颜色：前景、背景、光标、选区、16 个 ANSI 色（`crates/unifyterm/src/theme.rs`）。256 色里其余 240 个由它们算出。
- 内置只有一套（Tokyo Night）。设置文件的 `[theme]` 有 5 个键，可以逐个覆盖颜色。
- 标签栏、弹窗、列表、侧栏的颜色都从这 20 个颜色算出来（`toward`），`theme.rs` 之外没有写死的颜色。
- 窗口每 0.5 秒看一次设置文件，颜色在下一帧生效。
- 程序问终端"背景是什么颜色"（OSC 10/11）时，已经按主题回答。
- 窗口不知道系统是浅色还是深色，也不告诉系统自己是哪一种。

结论：换主题需要的机制（热更新、保存、派生颜色）已经都有。缺的只是"给一套颜色起名字"和"按名字选"。

## 用香农六法得出的决定

| 方法 | 结论 |
|---|---|
| 简化 | 主题 = 起了名字的 20 个颜色。切换 = 改一个设置项 `theme.name`。保存和热更新用现成的设置文件机制，不另造 |
| 相似问题 | Ghostty（`theme = 名字`，一个主题目录，`+list-themes`）、WezTerm（`color_scheme = "名字"`）、kitty（`kitten themes`）都是"一个名字 + 一个目录"。照这个做法 |
| 换说法 | "主题切换命令"不是给窗口发消息，是"改设置文件的一个值"。所以命令在窗口没开时也能用，对所有窗口同时生效 |
| 推广 | 内置主题和用户的主题用同一种文件、同一段读取代码：内置的只是编译进程序的文件。`ut theme show` 打印内置主题，就是用户写自己主题的起点 |
| 结构分析 | 三件事分开：一套颜色从哪来（名字 → 文件）；名字存在哪（设置文件）；谁来改名字（`ut theme`、`ut setting`、手改文件，三者等价） |
| 逆向 | 最坏的结果是换完主题看不清字、又换不回来。所以：切换前先检查文件；检查不过不写设置；`ut theme` 的输出不依赖主题也能读（用终端默认色）；再加一条"前景和背景对比度太低时提醒" |

## 设计

### 设置项

新增 1 个：`theme.name`，默认 `"tokyo-night"`。设置项 35 → 36。

颜色的来源，后面的盖住前面的：

1. `theme.name` 指的主题（找不到时用内置的 Tokyo Night）。
2. 设置文件 `[theme]` 里单独写的颜色（`theme.background` 等 5 个键，现有行为不变）。

这样现在已经在 `[theme]` 里改过颜色的用户，升级后看到的一样。

### 主题文件

一个主题一个 TOML 文件，键与 `[theme]` 相同：

```toml
# 文件名就是主题名：my-night.toml → my-night
foreground = "#c0caf5"
background = "#16161e"
cursor = "#c0caf5"        # 可省：用 foreground
selection = "#33467c"     # 可省：前景往背景靠 70% 的颜色
ansi = [                  # 16 个：黑红绿黄蓝紫青白，再是亮的 8 个
  "#15161e", "#f7768e", "#9ece6a", "#e0af68", "#7aa2f7", "#bb9af7", "#7dcfff", "#a9b1d6",
  "#414868", "#f7768e", "#9ece6a", "#e0af68", "#7aa2f7", "#bb9af7", "#7dcfff", "#c0caf5",
]
```

- `foreground`、`background`、`ansi` 必须有。原因：缺了就得从别的主题借，深色和浅色会混在一起。
- 不认识的键报错（防止拼错键名而不自知）。
- 名字只能是小写字母、数字和 `-`。

### 放在哪里

| 什么 | 位置 |
|---|---|
| 内置主题 | 仓库的 `themes/*.toml`，编译进程序 |
| 用户的主题 | 设置文件旁边的 `themes/` 目录（Windows：`%APPDATA%\unifyterm\themes\`） |

用户目录里与内置同名的文件优先：想微调内置主题，复制出来改即可。

### 命令：`ut theme`

```
ut theme                  列出主题：名字、内置还是自己的、一行色块；当前的有标记
ut theme NAME             切到 NAME：检查后把 theme.name 写进设置文件
ut theme show NAME        打印这个主题的文件内容（内置的也行）
ut theme new NAME [--from NAME]   在主题目录里建一个文件，内容抄自当前主题或 --from 的主题
ut theme check FILE       只检查一个文件
ut theme directory        打印主题目录
```

- 色块用真彩色转义序列打印，在任何支持真彩色的终端里都看得到主题的颜色，不用先切过去。
- `ut theme NAME` 写设置文件用 `ut setting` 现有的那段代码（保留文件里的注释和顺序）。
- `ut setting` 的界面里 `theme.name` 是一个可选列表（内置的加目录里的），不用打字。

### 窗口一侧

- 读设置时按 `theme.name` 取颜色。名字找不到或文件有错：保持现在的颜色，在标签页里说一行原因（与设置文件写错时相同），日志里记下。
- 正在用的主题文件也纳入每 0.5 秒的查看：改主题文件，窗口立即跟着变。写主题的人可以边改边看。用 M9 里加的"时间戳太新就过后再读一次"的规则。
- 把"现在是浅色还是深色"告诉系统（按背景色的亮度算）。原因：Windows 标题栏上的三个按钮、macOS 的红绿灯和系统画的边框要跟着变。这一项要先查 GPUI 0.2.2 能不能做到，做不到就写进已知限制。

## 浅色主题要查的地方

现在只有一套深色主题在用，下面这些在浅色下没人看过。实现时每一处截图看：

1. 标签栏、当前标签、关闭按钮。
2. 输入行下面的列表、弹窗（纠正、解释、同意）。
3. 灰色建议（前景往背景靠出来的颜色，浅色下够不够淡又看得清）。
4. agent 侧栏。
5. `ut setting` 自己的界面（它在终端里画，用 ANSI 色）。
6. `ut md`、`ut view` 的回退字符画。
7. 选区的文字是否还看得清。

## 不做的

| 项目 | 原因 |
|---|---|
| 跟随系统的浅色和深色自动切换 | 用户没有要。做的话是两个设置项（浅色时用哪套、深色时用哪套），可以以后加，不影响这次的文件格式 |
| 读别的终端的主题文件（kitty、Alacritty、Windows Terminal） | 先一种格式。以后加 `ut theme import FILE` 即可，不改现有的东西。iTerm2-Color-Schemes 有几百套现成的 |
| 在列表里上下移动时实时预览 | 色块已经能看出大概；切换本身只要一条命令、1 秒内生效，试一套的成本很低 |
| 主题里带字体、透明度、标签栏样式 | 主题只管颜色。其他的是设置项 |
| 窗口里的快捷键轮换主题 | 没有要 |
| 标签栏、弹窗的颜色单独指定 | 现在都从 20 个颜色算出来，一套主题不用多写。等有人觉得算出来的不好看再加 |

## 步骤（决定做之后）

1. `crates/config` 加 `themes`：读主题文件、内置表、按名字找、`theme.name` 这个设置项。单元测试：每套内置主题都能读；前景对背景的对比度不低于 7:1；先后顺序（主题 → `[theme]` 的键）。
2. 窗口：按名字取颜色；主题文件纳入查看；出错时的提示。
3. `ut theme`；`ut setting` 里的可选列表。
4. 10 套主题的文件，逐套核对许可和颜色值。
5. 浅色下的 7 处逐个截图，改掉看不清的。
6. 告诉系统深浅（先查 GPUI 能不能做）。
7. README、网页的数字（36 个设置）、`ut --help`。
8. 实机检查加一节：切换后背景像素变了；重开后保持；名字写错时不变。三轮验收。

估计改动量：新代码 600 到 900 行（不含主题文件），其中一半是测试。
