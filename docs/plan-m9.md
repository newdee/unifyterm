# M9：命令清单协议

2026-11-24 设计。路线图里的"下一步 2"。

## 目标

一个程序（先是 keepane）说明自己有哪些命令、选项和参数。UnifyTerm 把这份说明存下来，用在四处：

1. 打字时的提示（输入行下面的列表）。
2. 命令失败后的纠正。
3. 解释（Ctrl-Shift-E）。
4. 用一句话写命令（`#`）：给模型看，并核对模型的回答。

验收标准：

- keepane 的清单加进来后，`keepane sp` 的列表里有 `split-window` 和它的说明。
- `keepane splt-window` 失败后，弹窗给出 `keepane split-window`。
- `keepane split-window -h` 按 Ctrl-Shift-E，不用模型，立即得到每个词的说明。
- 模型写出清单里没有的子命令时，弹窗写明，并且不自动运行。
- 没有任何清单时，行为和 0.3.0 逐项相同。

## 用香农六法得出的决定

| 方法 | 结论 |
|---|---|
| 简化 | 最简单的版本：一个目录，一个程序一个文件。UnifyTerm 不运行任何程序，只读文件。其余传输方式（转义序列、运行程序取清单）以后都可以写进同一个目录 |
| 相似问题 | "说明一个命令行程序"已有现成格式：OpenCLI（JSON，MIT）、usage（KDL）、Fig spec（TypeScript）。不自造格式，用 OpenCLI 0.1 |
| 换说法 | "协议"不是一条通信通道，是两件事：一种文件格式，一个放文件的地方 |
| 推广 | 清单不只属于 keepane：OpenCLI 仓库里现成有 git、curl、ffmpeg、dotnet 四份。同一套代码对它们都要成立，所以按 2 MB 的文件来设计 |
| 结构分析 | 三层分开：读文件（格式）、存放处（目录）、四个使用者。使用者只见内存里的树，不见 JSON |
| 逆向 | 最坏的结果是清单里的文字变成被执行的命令。所以：名字里有空白或 shell 特殊字符的条目在读入时丢掉；清单里的文字只用来显示和交给模型，从不自动运行 |

## 格式：OpenCLI 0.1

来源：<https://github.com/spectreconsole/open-cli>（`draft.md`，MIT）。2026-11-24 取的版本，根对象是 `{opencli, info, command}`。

UnifyTerm 读这些字段，其余字段略过：

| 对象 | 字段 |
|---|---|
| 根 | `info.title`、`info.summary`、`info.description`、`info.version`、`command` |
| 命令 | `name`、`aliases`、`description`、`hidden`、`options`、`arguments`、`commands` |
| 选项 | `name`（带 `-`，如 `--quiet`）、`aliases`、`description`、`hidden`、`recursive`、`arguments` |
| 参数 | `name`、`description`、`acceptedValues`、`arity.minimum`、`arity.maximum` |

这个规范还是草案，2026-04-19 改过根对象。旧写法（根上直接有 `commands`、`options`、`arguments`，程序名在 `info.title`）也读。

读入时的限制：

- 文件最大 16 MB（ffmpeg 的清单 2.2 MB）；子命令最深 8 层。
- 程序名、命令名、选项名、别名、`acceptedValues` 里的值：有空白、控制字符或 `; | & $ \` < > ( ) { } ' " \ ! * ?` 之一的，丢掉这一条，并在 `ut program add` 的输出里报数。原因：这些词会被填到输入行上。
- 说明文字：去掉控制字符（换行和制表符除外）；只留第一段，最长 400 字符。

## 存放处

`<数据目录>/programs/<程序名>.json`。数据目录与历史库相同（`UNIFYTERM_DATA_DIR`，否则系统的本地数据目录下的 `unifyterm`）。

- 程序或用户把文件放进去，两种方法：`ut program add`，或直接写文件。
- 窗口在用到清单时看目录有没有变（最多每 2 秒看一次，比较文件名、大小、修改时间）。有变化时在另一个线程里重新读。加一份清单不用重开窗口。
- UnifyTerm 不运行任何程序来取清单。清单过期（程序升级后）由放文件的一方负责：升级后再运行一次 `ut program add`。

## 命令：`ut program`

```
ut program                     列出已有的清单：程序名、版本、命令数
ut program add FILE|-          检查后存入；`-` 从标准输入读
ut program check FILE|-        只检查，不存：给写清单的人用
ut program show NAME [WORD...] 打印清单里的一个命令：子命令、选项、参数
ut program remove NAME         删除
ut program directory           打印存放目录
```

keepane 一侧的用法：`keepane <打印清单的命令> | ut program add -`。

## 四个使用者

共同的前提：输入行是"简单的一条命令"，即没有 `| & ; < > ( ) { } $` 和反引号，引号成对。不满足时，1、2、3（本地部分）都不做。第一个词去掉 `.exe` 等扩展名、转成小写后与清单的程序名比较。

逐词走清单的规则（四处共用一个函数）：

- `--` 之后的词都是参数。
- 以 `-` 开头的词：在当前命令的选项、以及上层标了 `recursive` 的选项里找。`--name=value` 在 `=` 处分开。选项的第一个参数 `arity.minimum ≥ 1` 时，下一个词是它的值。
- 其他词：是当前命令的子命令（名字或别名）就进入它；否则，当前命令声明了参数就算参数；否则，当前命令有子命令就算"清单里没有的子命令"；都没有就算一个值，不报错（清单常常不全）。

### 1. 提示

- 列表里先是历史里的命令（和现在一样），后面是清单里的词，最多 6 行。
- 清单的行：正在打的词补全后的整行，右边是说明的第一句。
- 正在打的词以 `-` 开头：给选项。前一个词是要值的选项：给它的 `acceptedValues`。其他：给子命令和当前参数的 `acceptedValues`。`hidden` 的不给。
- 开关仍是 `history.candidates`（它管的是"输入行下面的列表"）。不加设置项。
- 键不变：上下选，Tab 或 Enter 放到输入行上，不运行。

### 2. 纠正

- 时机：命令失败（退出码不是 0）之后，现有的"找不到命令"的本地纠正没有结果时。开关仍是 `ai.fix`。
- 找第一个有问题的词：清单里没有的子命令，或清单里没有的 `--长选项`。离它 1 次按键（词长 ≤ 4）或 2 次按键以内有清单里的词，就给出换好的整行。
- 不报的情况：单个 `-x`（一个字母谈不上相近）；`--no-xxx` 而 `--xxx` 在清单里；当前命令一个选项也没声明。
- 弹窗和现在的纠正相同：Enter 放到输入行上，不运行。

### 3. 解释

- 第一个词在清单里，并且是简单的一条命令：不问模型，立即给出。每个词一行；选项和它的值合成一行。清单里没有的词写"不在 X 的清单里"。弹窗最后一行写明来源和"没有发送任何内容"。没有模型、没有同意过也能用。
- 其他情况照旧问模型。命令里有清单里的程序时，把该子命令的说明和选项一起交给模型（最长 8 KB），和现在交 `ut` 命令的 `--help` 是同一个位置。

### 4. 一句话写命令

- 发给模型的内容增加一段：每份清单一行（程序名和一句简介）；句子里或最近的命令里提到的程序，再给出它的命令表（名字、别名、选项名、一句说明）。整段最长 16 KB，超出就只给命令名和说明，再超出就截断。
- 模型回答后，用纠正用的同一个函数核对。有问题时：弹窗加一行"X 的清单里没有 Y"，并且不自动运行（即使 `ai.ask_enter = "auto"`）。

## 不做的

| 项目 | 原因 |
|---|---|
| 通过转义序列（OSC）声明 | `cat` 一个文件就能往清单里写东西，要先设计信任规则。远程机器上的程序需要它，以后做；到时写进同一个目录 |
| 运行程序取清单、每次按键问程序要补全（Cobra、clap、keepane 的 `__complete`） | 现有原则是不替用户运行别的程序。动态的值（会话名、窗格号）因此没有 |
| 读 usage（KDL）、Fig spec | 先一种格式。内存里的树与格式无关，以后可加 |
| shell 自己的命令（内建、别名、函数） | 是另一个来源（shell 钩子），不是程序的声明。M8 留下的"程序找不到"提示仍然等它 |
| 模型的灰色建议（`ai.suggest`）用清单 | 提示已有本地列表；3 秒的限时里不宜加长提示词 |
| 随 UnifyTerm 附带清单 | git 的清单 2 MB，版本跟着用户机器上的 git 走，不该由终端来带 |

## 实现时改动的决定（2026-11-24）

用 OpenCLI 仓库里真实的四份清单（git 1.95 MB、curl 0.47 MB、ffmpeg 2.2 MB、dotnet 0.81 MB）试过之后改的：

| 计划里的 | 实际做的 | 原因 |
|---|---|---|
| 解释里写出说明全文 | 每个词只写说明的第一句，最长 110 字符 | curl 的选项说明是整段文字，弹窗一行放不下 |
| 一组单字母选项（`-sSL`）按长名字列出 | 按打出来的字母列出（`-s: …; -S: …`） | 读的人看到的是 `-s`，不是 `--silent` |
| 当前命令声明了参数：词都算参数，不报 | 还没给过参数时，离某个子命令 1 到 2 次按键的词报出来并给出纠正 | `dotnet biuld` 原来不被纠正：dotnet 的根命令既有子命令又有参数（`dotnet app.dll`） |
| （没写） | 一个命令已经收到一个参数后，后面的词不再当作子命令 | `dotnet app.dll test` 里的 `test` 是程序的参数 |
| （没写） | 清单里没有的选项后面那个词，算作它的值 | `--prot 80` 里的 `80` 不该被报成"没有的子命令" |
| （没写） | 文件的开头不是 `{` 就拒绝 | serde 会把 JSON 数组按位置当成对象读进来 |
| （没写） | `ut program add` 删掉目录里描述同一程序的其他文件 | 否则按文件名排在前面的旧文件会顶替新的 |
| 清单的文字给模型：句子提到的程序 | 句子或最近 5 条命令提到的程序 | 用户正在用 keepane 时，说"把这个窗格分开"不会带上 keepane 这个词 |
| 同意弹窗的文字不变 | 加一句"用 `#` 时还发送程序对自己命令的说明" | 清单会让模型知道这台机器上有哪些程序 |

没有改的：格式、存放处、`ut program` 的六个用法、四个使用者各自的开关。

名字：crate 叫 `unifyterm-programs`；选项的类型叫 `Flag`（`Option` 是 Rust 自己的名字）。

量到的数字（debug 构建，本机）：

| 项目 | 数字 |
|---|---|
| 读四份真实清单（共 5.5 MB） | 16 ms |
| 补全、核对、解释各一次（git 的清单） | 0.03 到 0.46 ms |
| 5000 个命令、10 万个选项的清单（6 MB）：读入 | 62 ms |
| 同一份清单里补全一次 / 在 5000 个名字里找最近的 | 0.2 ms / 3.9 ms |
| 同一份清单给模型的文字 | 16380 字节（上限 16384） |
| dotnet 的清单读入时丢掉的条目 | 16 条（如别名 `-?`、`/?`：`?` 是 shell 的通配符） |

已知的不准确之处（都偏向不打扰）：

- `git co main`、`git lfs pull`：清单里没有 `co`（用户自己的别名）和 `lfs`（外部子命令）。失败后不弹纠正（附近没有清单里的词）；出现在模型的回答里时会写"git 的清单里没有 co"，并且不自动运行。
- `git log -5`：解释里 `-5` 写"不在 git 的清单里"。
- 清单的文字会原样进提示词。恶意的清单可以借此影响模型写出的命令；结果仍然只是填到输入行上，自动运行仍然只限白名单里的只读命令，且清单核对不过的不自动运行。
## keepane 一侧（不在本仓库）

keepane 需要一个打印 OpenCLI 文档的命令。它现有的表（`COMMANDS`、`FLAGS`、别名表）有名字和选项，没有每个命令的说明；说明要补。2026-11-24 已在 keepane 的群聊 `#unifyterm-keepane` 里提出（第 150 条），由 keepane 一侧实现。同日 keepane 一侧做出 `keepane opencli`，发来的清单（237 个命令、430 个选项）已在真实窗口里验过，结果在 `docs/verification-log.md`。

## 步骤

1. 新 crate `unifyterm-programs`（`crates/programs`）：读 OpenCLI、存放目录、逐词走清单、补全、核对、解释、给模型的文字。只依赖 serde。`distance` 从 assist 搬到这里，assist 改为引用。
2. `ut program`。
3. 窗口：列表里加清单的行；失败后的纠正；本地解释；`#` 的提示词和核对。
4. 文档：README 一节，`ut` 的帮助，skill 文件不改（agent 不用它）。
5. 验收三轮，记入 `docs/verification-log.md`。
6. 在群聊里把格式和命令告诉 keepane 一侧。
